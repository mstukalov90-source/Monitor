# SWEB — правила безопасности при миграции DMZ

**`77.222.63.161` (SWEB) — текущий рабочий прод.** Все внешние потребители (Android, смежники) сейчас подключены к нему.

Любое изменение на SWEB до cutover может прервать работу пользователей.

---

## Запрещено до явного cutover

| Действие | Риск |
|----------|------|
| `docker compose stop / restart / up / down` на SWEB | Остановка БД, API, collector |
| Изменение `/opt/monitor/.env` на SWEB | Сломать API-ключ, пароли, URL |
| Настройка firewall на SWEB | Отрезать клиентов от :5432 / :8000 |
| Установка nginx или другого ПО на SWEB | Конфликт портов, случайная остановка сервисов |
| `git pull` + `docker compose up --build` на SWEB | Непредсказуемые изменения в проде |
| Правка docs в `genplan api/`, `DEPLOY.md` (замена IP SWEB) | Сломать инструкции для текущих потребителей |
| Синхронизация данных SWEB ↔ `172.21.198.219` | Рассинхрон, двойная запись |

---

## Разрешено

| Действие | Комментарий |
|----------|-------------|
| Read-only: `curl http://77.222.63.161:8000/health` | Проверка, что прод жив |
| Read-only: `ssh ... 'docker compose ps'` | Мониторинг контейнеров, без изменений |
| Работа на `172.21.198.222` (DMZ) | Настройка прокси |
| Работа на `172.21.198.219` (Backend) | Firewall, `.env`, тесты |
| Создание docs в `mggt-DMZ/` | Не затрагивает SWEB |

---

## Почему настройка DMZ не вредит SWEB

SWEB (`77.222.63.161`) находится в публичном интернете. Серверы `172.21.198.x` — во внутренней корпоративной сети. **Прямой маршрут между ними отсутствует.**

Настройка nginx на `.222` и firewall на `.219` физически не может изменить состояние контейнеров на SWEB.

---

## Read-only мониторинг SWEB

```bash
# Health (без SSH)
curl -s http://77.222.63.161:8000/health

# Контейнеры (только просмотр)
ssh -i id_rsa/id_rsa root@77.222.63.161 'cd /opt/monitor && docker compose ps'
```

Ожидаемый ответ health: `{"status":"ok"}`

---

## Когда можно остановить SWEB

Только после выполнения [CUTOVER.md](CUTOVER.md):

1. DMZ полностью протестирован через `172.21.198.222`
2. Все потребители переключены на новый адрес
3. Cron на `172.21.198.219` стабилен ≥1–2 суток
4. Есть **явное согласование** на остановку SWEB

Команда остановки (только после согласования):

```bash
ssh -i id_rsa/id_rsa root@77.222.63.161 'cd /opt/monitor && docker compose stop'
```

Rollback (если нужно вернуть прод на SWEB):

```bash
ssh -i id_rsa/id_rsa root@77.222.63.161 'cd /opt/monitor && docker compose up -d'
```

Данные на SWEB не удалять минимум 1–2 недели после cutover.
